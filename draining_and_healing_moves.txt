3) EXACT EXECUTION WORKFLOW TO IMPLEMENT
--------------------------------------------------------------------------------

Turn workflow in Battle.executeRound():
1. Determine order by speed (current logic already exists).
2. First actor calls executeMove().
3. In executeMove():
   a) Precondition checks (null/fainted, dream-eater sleep gate)
   b) Status-heal move handling (roost/lunar-blessing)
   c) Accuracy check (if you add it)
   d) Damage calculation and defender.takeDamage(damage)
   e) applyPostDamageEffects(move, attacker, defender, damage)
   f) faint checks and notifications
4. Second actor executes if not fainted.
5. Existing faint-switch and battle end checks proceed unchanged.

--------------------------------------------------------------------------------
4) SUGGESTED CODE SKELETON (Battle.java)
--------------------------------------------------------------------------------

Use this structure to avoid scattered if/else blocks:

private void executeMove(PokemonInstance attacker, Move move, PokemonInstance defender) {
    if (move == null || attacker.isFainted()) return;

    String moveName = move.getName() == null ? "" : move.getName().toLowerCase();

    if ("dream-eater".equals(moveName)
            && defender.getStatusCondition() != PokemonInstance.StatusCondition.SLEEP) {
        notifyMoveFailed(attacker.getName(), move.getName(), "target is not asleep");
        return;
    }

    if (handleStatusMove(attacker, move)) {
        return;
    }

    int damage = calculateDamage(move, attacker, defender);
    defender.takeDamage(damage);
    notifyDamageDealt(attacker.getName(), move.getName(), defender.getName(), damage);

    applyPostDamageEffects(move, attacker, defender, damage);

    if (defender.isFainted()) {
        notifyPokemonFainted(defender.getName());
    }
}

--------------------------------------------------------------------------------

   - Drain effects should not heal when damageDealt == 0.

3. Dream Eater fail path:
   - Must fail before damage if target is not asleep.

4. Fainted defender:
   - Drain still heals based on damage dealt this hit (standard behavior).

5. Status-only moves when user already full HP:
   - Move still executes; healed amount may be 0.
   - Notify clearly: "restored 0 HP" or "HP is already full".

6. PP handling:
   - Ensure move PP decrements once when used (this likely occurs in higher-level
