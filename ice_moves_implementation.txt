            ICE TYPE MOVES — FULL IMPLEMENTATION GUIDE
            PokemonBattle Project (JavaFX / Gen 4 Dataset)
================================================================================

OVERVIEW
--------
This document covers every Ice-type move in moves_gen4.json, what they do,
what is already implemented, and exactly what code/functions/workflow needs to
be added or changed to fully implement each move's special mechanics.

There are 18 Ice-type moves in the dataset. The current engine
(Battle.java → calculateDamage) handles basic damage correctly for all of them
via type-effectiveness lookup (ICE = index 5 in the TYPE_EFFECTIVENESS chart).
What is missing are the secondary/special effects specific to each move.

================================================================================
WHAT IS ALREADY IMPLEMENTED
================================================================================

1. TYPE EFFECTIVENESS
   - Battle.java: TYPE_EFFECTIVENESS[ICE=5][defendingType] is fully populated.
   - ICE is super effective against: Grass(4)×2, Flying(9)×2, Ground(8)×2,
     Dragon(14)×2
   - ICE is not very effective against: Fire(1)×0.5, Water(2)×0.5,
     Ice(5)×0.5, Steel(16)×0.5
   - getTypeEffectivenessMultiplier() handles multi-type defenders correctly.

2. PHYSICAL vs SPECIAL DAMAGE
   - calculateDamage() already branches on move.getDamage_class():
     "special" → spAttack / spDefense
     "physical" → attack / defense
   - All 18 ice moves will use correct stats automatically.

3. STATUS MOVES (NO DAMAGE)
   - calculateDamage() returns 0 when power == null || power == 0
     OR damage_class == "status".
   - snowscape (id 529) and chilly-reception (id 603) return 0 damage.
   - WARNING: their actual effect (setting weather/switching) is NOT coded yet.

4. VISUAL ANIMATIONS — IceEffects.java
   The following visual categories are already implemented and are automatically
   selected inside IceEffects.createImpactEffect() by move-name keyword matching:

   BEAM (createBeamEffect via BattleAnimationManager.playRangedAnimation):
     → Triggered for all moves whose name contains "beam" OR "spear"
        (ice-beam, icicle-spear)
     → Cyan rectangle grows from attacker to defender; particles along path.

   FANG (addFangVisual):
     → moveName.contains("fang") → ice-fang
     → Two crystalline icicle fangs appear at defender, then shatter.

   BALL (addIceBallEffect):
     → moveName.contains("ball") → ice-ball
     → Glowing orb arcs from attacker to defender with ice shard explosion.

   WIND (addWindEffect):
     → moveName.contains("wind") OR "blizzard" OR "avalanche"
        → icy-wind, blizzard, avalanche
     → Multiple wind lines sweep across field with snowflakes.

   BREATH (addBreathEffect):
     → moveName.contains("breath") OR "reception" OR "freeze" OR "powder"
        → frost-breath, chilly-reception, freeze-dry, powder-snow
     → Mist clouds expand from attacker with light snowflakes.

   CRUSH (addCrushEffect):
     → moveName.contains("crush") → icicle-crash
     → Ice cubes fall from above and shatter on target.

   DEFAULT (addIceShardsAndSnowflakes):
     → All other ice moves: ice-punch, ice-spinner, aurora-beam, snowscape,
        ice-shard, triple-axel
     → Ice shards fly out + snowflake particles scatter.

5. MELEE vs RANGED ROUTING (BattleAnimationManager.java)
   - ice-punch → ATTACK_DISTANCE_FULL (punches close the gap)
   - Everything else ice → ATTACK_DISTANCE_SLIGHT
   - isRangedMove() → For ice, any move with "beam" or "spear" in the name
     is ranged (fires a projectile timeline, no attacker lunge).

6. AI MOVE SELECTION
   - getAIMove() in Battle.java already does type-effectiveness scoring for
     all moves, so AI will prefer ice moves against Flying/Dragon/Grass/Ground
     targets automatically.

MOVE 5: ice-fang (id 340)    — 10% FREEZE chance (OR 10% flinch)
--------------------------------------------------------------------------------

WHAT IT DOES:
  After dealing damage, there is a 10% chance to inflict the FROZEN status on
  the target. A frozen Pokemon cannot move until it thaws (randomly each turn,
  or after being hit by a Fire move). Ice-fang also has a separate 10% flinch
  chance on top of the freeze chance.

WHERE TO ADD THE CODE — Battle.java: executeMove()

  private void executeMove(PokemonInstance attacker, Move move, PokemonInstance defender) {
      if (move == null || attacker.isFainted()) return;

      // --- NEW: skip if frozen ---
      if (attacker.getStatus() == StatusCondition.FROZEN) {
          if (random.nextDouble() < 0.20) {            // 20% thaw chance per turn
              attacker.setStatus(StatusCondition.NONE);
              notifyStatusChanged(attacker.getName(), "thawed out");
          } else {
              notifyStatusChanged(attacker.getName(), "is frozen solid and can't move");
              return; // skip the move
          }
      }

      // --- NEW: skip if flinching ---
      if (attacker.isFlinching()) {
          notifyStatusChanged(attacker.getName(), "flinched and couldn't move");
          // flinching is cleared at start of next executeRound()
          return;
      }

      int damage = calculateDamage(move, attacker, defender);
      defender.takeDamage(damage);
      notifyDamageDealt(attacker.getName(), move.getName(), defender.getName(), damage);
      if (defender.isFainted()) {
          notifyPokemonFainted(defender.getName());
      }

      // --- NEW: secondary effects after damage ---
      applySecondaryEffect(move, attacker, defender);
  }

  // NEW METHOD to add:
  private void applySecondaryEffect(Move move, PokemonInstance attacker, PokemonInstance defender) {
      if (move == null || defender.isFainted()) return;
      String name = move.getName();

      switch (name) {
          // --- 10% Freeze chance ---
          case "powder-snow", "ice-punch", "ice-beam", "blizzard" -> {
              if (defender.getStatus() == StatusCondition.NONE && random.nextDouble() < 0.10) {
                  defender.setStatus(StatusCondition.FROZEN);
                  notifyStatusChanged(defender.getName(), "was frozen solid");
              }
          }
          // --- ice-fang: 10% freeze OR 10% flinch (handled separately) ---
          case "ice-fang" -> {
              double roll = random.nextDouble();
              if (defender.getStatus() == StatusCondition.NONE && roll < 0.10) {
                  defender.setStatus(StatusCondition.FROZEN);
                  notifyStatusChanged(defender.getName(), "was frozen solid");
              } else if (roll < 0.20) { // next 10% is flinch
                  defender.setFlinching(true);
                  notifyStatusChanged(defender.getName(), "flinched");
              }
          }
          // ... other cases below ...
      }
  }

  // NEW LISTENER NOTIFICATION METHOD:
  private void notifyStatusChanged(String pokemonName, String message) {
      for (BattleListener l : listeners) l.onStatusChanged(pokemonName, message);
  }

  // ADD TO BattleListener interface:
  void onStatusChanged(String pokemonName, String message);

MOVE 14: triple-axel (id 545) — 3 hits, power 20 / 40 / 60
--------------------------------------------------------------------------------

WHAT IT DOES:
  triple-axel hits exactly 3 times. Power of each hit increases:
  First hit: 20, second hit: 40, third hit: 60.
  Each hit has its own accuracy check (90%). If any hit misses, subsequent
  hits are cancelled.

WHERE TO ADD — Battle.java: executeMove() (special-case block)

  if ("triple-axel".equals(move.getName())) {
      int[] powers = {20, 40, 60};
      int totalDamage = 0;
      int hitsLanded = 0;
      for (int i = 0; i < 3; i++) {
          if (defender.isFainted()) break;
          // accuracy check per hit
          if (move.getAccuracy() != null && random.nextInt(100) >= move.getAccuracy()) {
              break; // missed, cancel remaining hits
          }
          // create a temporary Move with the right power for damage formula
          int dmg = calculateDamageWithPower(powers[i], move, attacker, defender);
          defender.takeDamage(dmg);
          totalDamage += dmg;
          hitsLanded++;
      }
      notifyDamageDealt(attacker.getName(), move.getName(), defender.getName(), totalDamage);
      if (hitsLanded > 0)
          notifyStatusChanged(attacker.getName(), "hit " + hitsLanded + " time(s) with triple-axel");
      if (defender.isFainted()) notifyPokemonFainted(defender.getName());
      return; // skip normal damage
  }

  // Helper that accepts an explicit power value:
  private int calculateDamageWithPower(int power, Move move, PokemonInstance attacker, PokemonInstance defender) {
      // Same as calculateDamage but power is passed in, not from move.getPower()
      int atkStat = "special".equals(move.getDamage_class()) ? attacker.getSpAttack() : attacker.getAttack();
      int defStat = "special".equals(move.getDamage_class()) ? defender.getSpDefense() : defender.getDefense();
      double damage = ((2.0 * attacker.getLevel() / 5.0 + 2.0) * power * atkStat / (double) defStat) / 50.0 + 2.0;
      float effectiveness = getTypeEffectivenessMultiplier(move.getType(), defender.getTypes());
      damage *= effectiveness;
      damage *= (0.85 + random.nextDouble() * 0.15);
      return Math.max(1, (int) damage);
  }

HOW FLINCH INTERACTS WITH TURN ORDER:
  Flinch only prevents the move if the defender hasn't attacked yet this round.
  In executeRound(), moves execute in sequence. If ice-crash fires first and
  sets flinching=true, and then the flinched pokemon's turn comes in executeMove(),

  sequential structure already in executeRound(). Clear flinching at the top
  of the NEXT executeRound() call.

ICE TYPE EFFECTIVENESS REFERENCE
================================================================================

Ice moves are SUPER EFFECTIVE (×2) against:
  - Grass         (Bulbasaur, Chikorita, Turtwig, etc.)
  - Flying        (Pidgeot, Gyarados, Dragonite, etc.)
  - Ground        (Sandslash, Rhydon, etc.)
  - Dragon        (Dragonair, Garchomp, etc.)

Ice moves are NOT VERY EFFECTIVE (×0.5) against:
  - Fire          (Charizard, etc.)
  - Water         (Blastoise, etc.) — NOTE: freeze-dry OVERRIDES this to ×2
  - Ice           (Jynx, Lapras, etc.)
  - Steel         (Skarmory, Magnezone, etc.)

Ice moves deal NORMAL DAMAGE (×1) against all other types.

In Battle.java the ICE row of the TYPE_EFFECTIVENESS chart is:
  chart[5][8]  = 2.0f;  // ICE vs GROUND
  chart[5][9]  = 2.0f;  // ICE vs FLYING
  chart[5][4]  = 2.0f;  // ICE vs GRASS
  chart[5][14] = 2.0f;  // ICE vs DRAGON
  chart[5][1]  = 0.5f;  // ICE vs FIRE
  chart[5][3]  = 0.5f;  // ICE vs ELECTRIC (wrong — should be ×1)
  chart[5][5]  = 0.5f;  // ICE vs ICE
  // MISSING from chart[5]: chart[5][2] = 0.5f (ICE vs WATER)
